# 校宝核心模块对齐差距审计

更新日期：2026-09-14

## 1. 审计目的

本次审计不以“功能名称是否相同”为标准，而以校宝专业版的真实信息架构、页面字段、操作路径、批量能力和状态规则为标准，评估当前自建系统在“学生管理、成绩管理、角色权限和工作台”四个核心区域中的差距。

审计使用已登录的校宝专业版账号，仅查看页面和交互结构，不修改校宝中的业务数据，不记录真实学员、家长或员工个人信息。

## 2. 总体结论

当前系统已经具备基础数据链路，但仍属于“可以用”的业务原型，不是“像校宝一样能日常运营”的管理系统。主要差距集中在以下五层：

1. **信息架构**：当前是平铺菜单；校宝是九大中心、分组菜单、子页签和面包屑组成的多级导航。
2. **工作台**：当前只有简单统计入口；校宝把待办、风险、快捷操作、今日经营、初始化引导集中在一个工作台。
3. **业务对象**：当前学生档案字段过少；校宝学生是包含报名、班级、成绩、订单、成长记录、账户、微信关注和考勤信息的工作区。
4. **批量操作**：当前多数页面以单条新增为主；校宝的列表页普遍具备筛选、批量选择、批量编辑、导出、自定义列和导入。
5. **权限粒度**：当前是少量模块勾选；校宝按预置角色、具体权限项和适用校区三层控制，并支持员工多角色。

## 4. 重点页面对齐结论

### 4.1 工作台

校宝工作台不是装饰页，而是每日工作入口，至少包含：

- 机构认证和风险提示。
- 按课时、按时间、按期学员到期提醒。
- 待处理欠费、待考勤、待点评作业、待回访等待办。
- 初始设置检查清单。
- 常用功能：咨询记录、报名续费、排课、记上课。
- 今日总览和当前经营数据。

当前系统需要把工作台从“入口页”升级为“待办驾驶舱”，否则即使底层数据完整，使用者也不知道每天先做什么。

### 4.2 学员管理

校宝的学员列表是运营型列表，不是普通档案表。必须按以下优先级补齐：

1. 服务端分页、姓名/拼音搜索和多条件筛选。
2. 可配置列、列表状态标签和主要字段展示。
3. 批量导入、导出、通知、调整校区/课程和批量删除。
4. 点击学员进入详情工作区。
5. 学员详情至少包含基础信息、家长关系、报读课程、班级、上课记录、成绩、成长记录、订单、账户和操作日志。

当前系统的学员表无法支撑校区的日常查询、家长沟通和续费跟踪，这是最优先修复的模块。

### 4.3 成绩管理

校宝的成绩模型已经从“一条成绩”升级为“项目设置 + 考试设置 + 成绩记录”：

- 项目设置：项目名称及项目维护。
- 考试设置：考试名称及考试维护。
- 成绩管理：学员、关系、联系方式、项目、成绩、来源、考试日期、考试、班级、备注和操作。
- 成绩录入：机构内/机构外、项目、考试日期、考试、从班级选学员、按班级分组输入、缺考留空。

当前系统已有三层数据基础，但前端录入体验仍偏“开发工具”。下一版需要把“选班级 → 选项目 → 选考试 → 批量填分 → 保存”做成校宝式连续工作流，并支持按来源筛选和导出。

### 4.4 角色权限

校宝角色页的关键不是角色名称，而是三层结构：

1. 左侧选择角色，支持新建、重命名和删除。
2. 中间选择适用校区：全部校区或指定校区。
3. 右侧按业务中心选择权限，并明确提示修改角色会影响已有员工。

权限项需要按招生、办理、教务、校宝家、内部管理、报表、工作台、财务、教材、电子合同、考勤、移动端和机构中心等分组，而不是简单平铺。

当前系统已有角色表和模块权限表，但页面与业务权限语义距离较远，需要重新设计角色编辑工作台和员工角色分配流程。

## 5. 建议的对齐批次

### 第一批：核心工作流对齐

范围：

- 全局导航、面包屑和页面页签框架。
- 工作台待办与常用入口。
- 学员列表、筛选、批量操作和学员详情。
- 成绩管理、项目设置、考试设置和成绩录入工作流。
- 角色权限工作台和员工多角色展示。

目标：让行政、教务和教师可以按照校宝的日常路径完成“找学员、看档案、录成绩、分配权限”的核心工作。

### 第二批：教务运营闭环

范围：

- 课程、班级、一对一。
- 排课视图、冲突处理和记上课。
- 报读、课时账户、考勤和成长记录。

### 第三批：经营与家校闭环

范围：

- 订单、充值、补费、转课、退费、教材杂费。
- 课堂点评、作业、通知公告、家长申请。
- 经营报表、财务对账、员工报表和数据导出。

## 6. 第一批验收标准

- 页面导航按业务中心分组，并能通过真实角色权限隐藏无权模块。
- 工作台可以看到待处理事项，并点击进入对应处理页。
- 学员列表支持分页、组合筛选、批量操作和自定义列。
- 学员详情至少展示基础信息、报读课程、班级、成绩、成长记录、订单和操作日志。
- 成绩页可按项目、考试、日期、来源查询，并可完成一次批量录入。
- 角色编辑支持适用校区、权限分组、保存、重命名和删除。
- 员工可以拥有多个角色，并在列表中正确展示。
- 关键流程有后端测试、前端类型检查和浏览器冒烟验证。

## 7. 暂不纳入第一批

- 公众号、营销活动、拼团、砍价、分销等招生运营能力。
- AI 学员运营、AI 风险预警、AI 数据分析。
- 电子合同、工资条、数据大屏。
- 真实微信推送和短信通道。
- 第三方支付、电子签章和外部平台直连。

这些能力需要独立的产品设计、外部账号和合规确认，不应混入第一批核心工作流对齐。
