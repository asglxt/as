# 学校管理系统设计（一期）

日期：2026-08-13

## 1. 背景与目标

学校（培训机构，学员 1000 人以上，多校区）希望自建一套类似校宝的学生管理与成绩管理系统。自建的主要动机：降低长期费用、摆脱现成软件定制困难、掌握数据主权、让系统贴合本校教学与管理流程。

一期目标：把学员管理与成绩管理先跑起来，行政和教师日常可用，家长/学生可以在手机浏览器查看自己孩子的成绩与报告。

## 2. 用户与角色

- 行政：管理全校数据，负责学员档案、班级、考试、导入导出、账号与权限。
- 教师：只能查看和录入自己任教班级的学员与成绩。
- 家长：通过学校邀请码绑定孩子，只能查看自己孩子的成绩与报告。
- 学生：查看自己的成绩与报告。

一期行政默认可管理全校；按校区分权的校区管理员作为二期扩展点，不在本期实现。

## 3. 功能范围

### 一期

- 组织与权限：机构、校区、班级层级；四类角色；后端强制权限校验。
- 学员档案与班级：学员档案增删改查、分班、转班、在读/停用/结业状态。
- 成绩管理：考试测评管理（单元测/期中/期末/等级考等类型），百分制、等级制、积分制、评语；按班级批量录入；Excel 导入；平均分、及格率、优秀率、排名、进步趋势分析；报告单打印、导出、家长/学生端查看。
- 数据导入：从 Excel/校宝导出文件导入学员、班级、成绩；先校验后入库；错误精确到行和列。
- 家长/学生端：手机浏览器适配，查看成绩、报告、历史趋势。

### 二期（本期不实现，架构预留）

- 考勤管理：上课打卡、请假、缺课统计。
- 报名合同与财务：报名、续费、合同、收据、退费、对账。

### 三期（预留）

- 家校沟通：通知、作业、课堂点评、消息中心。
- 更细的经营分析报表。

## 4. 核心流程

1. 行政导入或录入学员与班级。
2. 教师建立考试测评，为班级录入成绩，或行政通过 Excel 批量导入。
3. 系统自动生成成绩分析与报告。
4. 家长/学生登录后查看自己孩子的成绩、报告与趋势。

## 5. 数据模型

核心实体：

- 机构：系统根节点，包含所有校区。
- 校区：业务数据归属单位，包含部门/班级。
- 班级：科目、年级、上课时间、授课教师；学员可同时属于多个班级。
- 学员档案：姓名、家长联系方式、在读班级、状态（在读/停用/结业）。
- 教师/员工：归属校区、任教班级、角色。
- 家长/学生账号：通过邀请码绑定学员，一个账号可绑定多个孩子。
- 考试测评：名称、类型、班级、日期、满分、评分方式。
- 成绩记录：学员 × 考试 × 分数/等级/积分/评语；记录录入人和修改历史。
- 报告单：成绩汇总、排名、评语、趋势，可打印/导出/家长端查看。
- 导入任务：上传文件、校验结果、错误明细、导入状态。
- 操作日志：关键写操作留痕，尤其是成绩修改。

## 6. 权限模型

| 操作 | 行政 | 教师 | 家长 | 学生 |
| --- | --- | --- | --- | --- |
| 查看本校区学员/班级 | 全校 | 自己班级 | - | - |
| 新增/编辑学员档案 | 有 | - | - | - |
| 录入/修改成绩 | 有 | 自己班级 | - | - |
| 查看成绩分析与报表 | 有 | 自己班级 | - | - |
| 查看自己孩子/自己的成绩报告 | - | - | 有 | 有 |
| 数据导入/导出 | 有 | - | - | - |

权限在后端统一校验，前端隐藏入口仅作为辅助。成绩修改保留操作记录。

## 7. 技术架构

- 前端：React + TypeScript（Vite），响应式布局，桌面端与手机浏览器共用。
- 后端：Node.js + TypeScript 提供 REST API，JWT 会话认证。
- 数据库：PostgreSQL，集中存储多校区数据。
- 部署：Docker Compose 部署到单台云服务器，Nginx 提供 HTTPS 反向代理。
- 可移植性：应用和数据保持标准结构，后续可按需迁移到学校自建服务器。
- 备份：PostgreSQL 每日自动备份并同步到异地存储，保留 30 天；支持手动导出和一键恢复。

## 8. 错误处理与安全

- 登录：密码加密存储，登录限流防爆破；家长/学生通过邀请码绑定。
- 数据隔离：成绩等敏感数据按角色和班级边界隔离。
- 删除保护：有成绩或业务记录的学员不允许直接删除，只能停用/归档。
- 导入错误：校验结果精确到“第几行哪一列”，支持修正后重新导入。
- 异常处理：用户看到友好提示，不暴露内部堆栈，错误写入日志。
- 合规：学生与家长个人信息最小化收集；支持按政策要求导出或删除个人数据。

## 9. 测试策略

- 单元测试：权限规则、成绩计算、导入校验。
- 集成测试：核心 API 数据流（建班 → 录成绩 → 家长查看）。
- 端到端测试：一期核心流程全链路走通。
- 浏览器 QA：桌面端和手机端尺寸检查，重点页面不重叠、不溢出。

## 10. 一期验收标准

1. 行政能从 Excel/校宝导出文件导入学员和成绩，并看到错误报告。
2. 教师只能录入自己班级的成绩，行政可以全校录入。
3. 家长/学生登录后只能看到自己孩子/自己的报告。
4. 多校区数据互不串，成绩修改有记录。
5. 每日备份可以恢复。

## 11. 假设与边界

- 一期部署到单台云服务器（假设国内主流云厂商），使用 Docker Compose，不涉及 Kubernetes。
- 校宝导出文件样例在实施阶段由学校提供，用于校准导入模板。
- 一期不做考勤、报名合同、财务、家校沟通；这些模块只保留架构扩展点。
- 家长绑定采用学校生成的邀请码，不开放自助注册。
- 学员状态支持在读、停用、结业；删除通过归档代替。
