# 二期 2A 设计：教务与课时闭环

日期：2026-09-14
状态：设计已通过用户确认（待写入实施计划）
调研依据：`docs/superpowers/research/2026-09-14-schoolpal-system-analysis.md`（校宝 33 个页面/模块实测）

## 1. 背景与目标

一期已完成：多校区组织、学员档案、班级、考试/成绩（单分数模型）、CSV 导入、家长/学生端查看成绩。

二期拆成 2A（本设计）与 2B：
- 2A 教务与课时闭环：角色权限 → 课程 → 班级/分班 → 教室 → 排课 → 报读/课时账户 → 记上课。
- 2B 成绩与家校 + 完整财务：成绩模型升级、课堂点评、作业、订单/收款/退费/充值/教材杂费、报表。

2A 目标：让学校能真正跑起来「建课 → 开班 → 分班 → 排课 → 上课 → 点名 → 扣课时」的日常闭环。

## 2. 范围

### 2A 包含

- 可配置的角色权限：角色 + 适用校区 + 模块权限；员工可多角色。
- 课程体系：课程类别、科目、课程、升期关系。
- 班级与分班：班级挂课程/校区/班主任/助教；分班记录。
- 教室资源：按校区维护教室。
- 排课：时间/教师/教室/班级四种视图，创建/编辑，冲突检测。
- 报读与课时账户：学员报读课程，录入购买课时与金额，课时流水。
- 记上课：一节课一条记录，点名（到课/缺课/请假/补课），自动扣课时，补记上课，课时汇总。
- 关键操作审计日志。

### 2A 不包含（留给 2B 或更后）

- 成绩模型升级（项目/考试字典）。
- 课堂点评、作业、成长记录、通知公告。
- 订单/收款/退费/充值/教材杂费、电子合同。
- 报表中心、家长端推送、招生营销、工资绩效。
- 人脸/磁卡考勤硬件对接。

## 3. 角色与权限模型

- 角色（roles）：名称、是否预置、启用状态。
- 角色权限（role_permissions）：角色 × 模块。
- 角色校区（role_campuses）：角色 × 适用校区；支持「全部校区」。
- 员工角色（user_roles）：员工 × 角色，支持一人多角色。
- 模块清单（2A 范围）：工作台、学员、班级、课程、排课、记上课、报读、教室、组织架构、员工、角色权限、报表（预留）。
- 校验规则：
  - 后端每个接口按「模块权限 + 校区范围」校验，未授权返回 403。
  - 前端按权限渲染菜单与页面入口。
  - 一期已有的 admin/teacher/parent/student 继续可用：admin 视为超级管理员，拥有全部权限。
- 兼容：一期 `users.role` 保留，新增的角色权限作为扩展；admin 不受角色表限制。

## 4. 数据模型

### 4.1 权限

    roles(id, name, is_preset, enabled, created_at)
    role_permissions(role_id, module_key)
    role_campuses(role_id, campus_id)          -- campus_id 为空表示全部校区
    user_roles(user_id, role_id)

### 4.2 课程

    lesson_categories(id, name, sort, enabled)
    subjects(id, name, sort, enabled)
    lessons(
      id, name, category_id, subject_id,
      teaching_mode,        -- 一对一 / 小班 / 大班
      fee_mode,             -- 按课时 / 按期 / 按时间
      campus_id,            -- 空表示全校区
      status,               -- 开售 / 停售
      created_at
    )
    lesson_upgrades(id, from_lesson_id, to_lesson_id, sort)

### 4.3 班级与分班（扩展一期表）

    classes 新增：lesson_id, campus_id, teacher_id, assistant_id,
                capacity, start_date, class_time, recruit_status, status
    class_students 新增：lesson_id, teacher_id, start_date, status, is_upgraded

### 4.4 教室

    classrooms(id, campus_id, name, capacity, status, created_at)

### 4.5 排课

    schedules(
      id, class_id, campus_id, schedule_date,
      start_time, end_time,
      teacher_id, classroom_id,
      is_recorded,       -- 是否已记上课
      has_trial,         -- 是否含试听学员
      status,            -- 正常 / 已取消
      created_by, created_at
    )

### 4.6 报读与课时账户

    enrollments(
      id, student_id, lesson_id, campus_id,
      purchased_hours, used_hours, remaining_hours,
      total_fee, paid_fee, used_fee, remaining_fee, arrears,
      status,            -- 在读 / 停课 / 结课 / 退费
      enrolled_at, created_at
    )
    hour_transactions(
      id, enrollment_id, student_id,
      type,              -- 购买 / 消耗 / 调整 / 退费
      hours,             -- 正数增加，负数减少
      balance_after,
      teaching_log_id,   -- 消耗时关联
      remark, created_by, created_at
    )

### 4.7 记上课与点名

    teaching_logs(
      id, schedule_id, class_id, campus_id,
      teacher_id, classroom_id,
      status,            -- 未记录 / 已记录
      taught_at,
      recorded_by, recorded_at,
      remark
    )
    attendance_records(
      id, teaching_log_id, student_id,
      status,            -- 到课 / 缺课 / 请假 / 补课
      hours_deducted,    -- 实际扣减课时
      remark,
      created_at
    )

### 4.8 审计

沿用一期 `audit_logs`，2A 关键操作全部写入：排课创建/修改、记上课、点名、课时调整、报读创建。
## 5. 页面与功能

### 5.1 角色权限

- 角色列表；新建/编辑/复制/删除角色。
- 编辑角色：名称、适用校区（全部/指定多选）、模块权限勾选。
- 员工分配角色：在员工详情中多选角色，展示合并后的权限与校区范围。
- 未授权模块：菜单不显示；直接访问 URL 返回无权限页。

### 5.2 课程

- 课程列表：课程名称、类别、科目、授课模式、收费模式、开课校区、开班数、状态、创建日期；支持筛选与搜索。
- 新建/编辑课程：名称、类别、科目、授课模式、收费模式、开课校区、状态。
- 课程类别：名称、排序、启用。
- 科目设置：名称、排序、启用。
- 升期关系：配置「从课程 → 到课程」的升级路径与排序。

### 5.3 班级

- 班级列表：班级名称、所属课程、人数、班主任、助教、开班校区、开班日期、上课时间、招生状态、操作。
- 页签：班级列表、分班、操作日志。
- 新建/编辑班级：课程、校区、名称、班主任、助教、满班人数、开班日期、上课时间、招生状态。
- 分班：把学员加入班级（选择报读课程），记录分班状态与是否升期；支持转班与结班。

### 5.4 教室

- 按校区维护教室：名称、容量、状态。
- 教室用于排课选择与冲突检测。

### 5.5 排课

- 四种视图：时间课表、教师课表、教室课表、班级课表。
- 筛选：班级/一对一名称、校区、教师、教室、课程类别、课程、科目、是否记上课。
- 周视图默认展示当前周（周一至周日，7:00-22:00）。
- 新建/编辑排课：班级、日期、开始/结束时间、教师、教室、备注。
- 冲突检测：同一教师、同一教室、同一班级在时间重叠时禁止保存，并提示冲突对象。
- 课程卡片显示：校区 + 班级 + 教师 + 教室；教师未定显示「待定」。

### 5.6 报读与课时账户

- 报读列表：学员、课程、购买课时、已用课时、剩余课时、总学费、实缴、欠费、报读校区、状态。
- 新建报读：选择学员与课程，录入购买课时与总学费/实缴金额（金额仅记录，不做收款流程）。
- 课时调整：手动增加/减少课时，必须填写备注，写入课时流水。
- 课时流水：按学员/课程查看购买、消耗、调整、退费记录与变动后余额。

### 5.7 记上课

- 今日上课：按日期列出当天每节课（班级、课程、教师、校区、教室、状态）。
- 记上课：选择一节课 → 列出学员名单 → 逐个标记到课/缺课/请假/补课 → 保存。
- 自动扣课时：到课扣 1 课时（或按班级课时设置）；缺课按学校规则是否扣课时（默认扣，可配置）；请假不扣；补课按规则扣。
- 补记上课：对过去未记录的课补录。
- 课时汇总：按学员/班级统计已上课时与剩余课时。
- 记上课完成后回写 `schedules.is_recorded = true`。

## 6. 关键流程

### 6.1 排课

1. 管理员/教务选择班级、日期、时间段、教师、教室。
2. 系统校验教师/教室/班级冲突与教室容量。
3. 保存后生成 `schedules` 记录，`is_recorded` 为 false。

### 6.2 记上课与扣课时

1. 教师在「今日上课」选择一节课。
2. 系统列出该班级当前在读学员。
3. 教师标记出勤状态并保存。
4. 系统为每条出勤记录写入 `attendance_records`，按规则计算 `hours_deducted`。
5. 对扣课时的学员，更新 `enrollments.used_hours/remaining_hours` 并写入 `hour_transactions`。
6. 更新 `teaching_logs.status = 已记录`、`schedules.is_recorded = true`；写审计日志。

### 6.3 扣课时规则（2A 默认）

- 到课：扣 1 课时。
- 缺课：默认扣 1 课时（可在机构设置中改为不扣）。
- 请假：不扣课时。
- 补课：按 1 课时扣减（补课记录单独标记）。
- 剩余课时不足：允许保存但标记欠课时，并在课时汇总中提示。

## 7. 兼容与迁移

- 只新增表，不改动一期已有业务数据；`classes`、`class_students` 通过增加可空字段扩展。
- 一期成绩与家长端功能不受影响；2B 再做成绩模型升级。
- 现有 `admin` 用户自动拥有全部权限；既有教师账号默认映射为「教师」预置角色。
- 预置角色（与校宝对齐）：机构主管、校区主管、教务、教师、前台、财务、人事、市场主管、销售员、班务（2A 至少提供机构主管/校区主管/教务/教师四个可用角色）。
## 8. 验收标准

1. 管理员能创建自定义角色，勾选模块权限并指定适用校区；员工可被分配多个角色，登录后只看到授权模块。
2. 能维护课程类别、科目、课程与升期关系；课程列表显示开班数。
3. 能创建班级（挂课程/校区/班主任/助教/满班人数/上课时间）并对学员分班、转班。
4. 能按校区维护教室。
5. 能创建排课；教师、教室、班级时间冲突会被拦截并给出冲突提示。
6. 能给学员报读课程，录入购买课时与金额；课时流水可查。
7. 教师能对当天的课记上课并点名；到课/缺课/请假/补课状态正确，扣课时与课时流水一致。
8. 排课记录能正确回写「是否已记上课」，课时汇总数据与流水一致。
9. 关键操作（排课、记上课、点名、课时调整、报读）都有审计日志。
10. 一期已有功能（学员、成绩、导入、家长端查看成绩）不回归。

## 9. 假设与边界

- 2A 的金额字段只做记录，不做收款/对账流程；收款与退费在 2B。
- 一期成绩表保持不动，2B 再升级为「项目 + 考试 + 学员成绩」。
- 机构设置（缺课是否扣课时、每日课时数）先提供全局默认值，校区级配置留到后续。
- 教室容量仅记录，不做自动排座位。
- 家长端在 2A 不新增推送；家长仍可查看成绩（一期功能）。
- 排课冲突检测按「时间段重叠」判断，不处理跨天课程（2A 不涉及）。

## 10. 风险与对策

- 风险：课时账户是财务级数据，扣减必须可追溯。对策：所有课时变动必须写 `hour_transactions`，不允许直接改余额。
- 风险：排课冲突检测易出现边界问题。对策：统一用「开始时间 < 对方结束时间 且 结束时间 > 对方开始时间」判断重叠，并写单元测试覆盖边界。
- 风险：权限模型改造影响一期接口。对策：admin 保持全权限，既有接口默认放行给 admin，新增模块才走角色权限表。
- 风险：范围较大导致交付周期长。对策：按模块增量交付，每个模块完成后即可使用并验收。
