# 三期 2B-3 设计：报表中心

日期：2026-09-14
状态：设计已确认（按用户授权采用推荐方案）
调研依据：`docs/superpowers/research/2026-09-14-schoolpal-system-analysis.md` 第 10.23 节（报表中心实测）

## 1. 背景与目标

一期、2A、2B-1、2B-2 已完成：组织权限、课程班级、排课记上课、报读课时、成绩点评作业、订单收款退费。

2B-3 目标：把沉淀的业务数据变成可用报表——按「校区 × 时间」看经营、教务、财务、员工四类指标，支持环比、校区对比与明细下钻。

## 2. 范围

### 2B-3 包含

- 经营总览：核心指标卡（在读学员、新增报名、排课数、已上课时、应收、实收、欠费、退费、学员余额）+ 环比。
- 招生与学员：新增学员趋势（按日/周/月）、校区对比、学员状态分布。
- 教务：排课数、上课记录数、课时消耗、出勤率（到课/缺课/请假）、补课数。
- 财务：应收、实收、欠费、退费、充值、余额；校区对比；订单类型分布。
- 员工：员工数、教师数、带班数、班级数。
- 下钻：新增学员明细、欠费订单明细、课时消耗明细、退费记录明细。
- 图表：ECharts 折线（趋势）、柱状（校区对比）、饼图（分布）。

### 2B-3 不包含

- 数据大屏（多屏拼接、自动轮播）。
- AI 数据分析助手。
- 招生咨询/线索报表（系统暂无咨询数据源）。
- 自定义报表设计器与导出为 Excel（本期支持 CSV 导出）。

## 3. 数据来源

全部基于已有表，不新增业务表（仅新增权限）：

- 学员：`students`、`class_students`
- 教务：`schedules`、`teaching_logs`、`attendance_records`
- 财务：`orders`、`payments`、`refunds`、`enrollments`、`student_accounts`
- 组织：`users`、`roles`、`user_roles`、`classes`、`campuses`
- 成绩（可选）：`student_scores`

## 4. 接口设计

- `GET /api/reports/overview?campusIds=&start=&end=&compare=prev`
  返回：在读学员、新增报名、排课数、已上课时、应收、实收、欠费、退费、余额，以及每个指标的环比。
- `GET /api/reports/students?campusIds=&start=&end=&granularity=day|week|month`
  返回：新增学员趋势数组、校区对比数组、学员状态分布。
- `GET /api/reports/teaching?campusIds=&start=&end=`
  返回：排课数、上课记录数、课时消耗、出勤率明细（到课/缺课/请假/补课）。
- `GET /api/reports/finance?campusIds=&start=&end=`
  返回：应收/实收/欠费/退费/充值/余额、校区对比、订单类型分布。
- `GET /api/reports/employees?campusIds=`
  返回：员工数、教师数、带班数、班级数。
- `GET /api/reports/drilldown?metric=&campusIds=&start=&end=`
  返回对应明细行（学员/订单/课时/退费），支持分页。

所有接口要求 `report` 模块权限；校区范围按用户角色的适用校区过滤（admin 全校区）。

## 5. 页面设计

- 顶部筛选条：校区多选（默认全部）、时间范围（今日/昨日/本周/上周/本月/上月/今年/自定义）、粒度（日/周/月）。
- 五个页签：经营总览、招生与学员、教务、财务、员工。
- 指标卡：数值 + 环比箭头（上升/下降/持平）+ 点击下钻。
- 图表区：ECharts 折线/柱状/饼图，随筛选联动。
- 下钻弹窗：明细表格（支持 CSV 导出）。

## 6. 技术实现

- 前端：新增 `ReportsPage.tsx`；引入 `echarts`（趋势/对比/分布图）；下钻用弹窗 + 表格。
- 后端：新增 `server/src/routes/reports2.ts`（与一期 `reports.ts` 的家长端报告区分），聚合 SQL 直接查询。
- 权限：`ModuleKey` 与 `ALL_MODULES` 增加 `'report'`；预置角色机构主管/校区主管/财务默认拥有。
- 校区过滤：从当前用户的角色校区范围解析允许的 campusIds；admin 不限。
- 性能：报表查询加时间范围与校区条件；为高频查询（订单按时间、上课记录按时间）确认已有索引，必要时补充索引。

## 7. 验收标准

1. 管理员能打开报表中心，看到经营总览指标卡与环比。
2. 能按校区与时间范围筛选，图表与指标随筛选变化。
3. 招生与学员页显示新增学员趋势、校区对比、状态分布。
4. 教务页显示排课数、上课记录数、课时消耗与出勤率。
5. 财务页显示应收/实收/欠费/退费/充值/余额与订单类型分布。
6. 员工页显示员工数、教师数、带班数、班级数。
7. 指标可下钻到明细致（新增学员 / 欠费订单 / 课时消耗 / 退费记录），并能导出 CSV。
8. 无 report 权限的教师访问返回 403。
9. 一期、2A、2B-1、2B-2 功能不回归。

## 8. 假设与边界

- 金额口径：应收 = 订单 receivable 合计；实收 = payments 合计；欠费 = 订单 arrears 合计；退费 = refunds.actual_amount 合计；充值 = recharge 订单实收合计；余额 = student_accounts.balance 合计。
- 课时消耗 = attendance_records 中 hours_deducted 合计。
- 出勤率 = 到课 /（到课 + 缺课 + 请假 + 补课）。
- 环比 = 与上一同等长度周期比较，百分比保留一位小数。
- 时间默认「本月」，校区默认「全部」。

## 9. 风险与对策

- 风险：全表聚合在数据量大时变慢。对策：按时间与校区过滤，并为 orders.created_at、teaching_logs.taught_at、attendance_records.created_at 增加索引。
- 风险：校区权限过滤遗漏导致越权看数据。对策：所有报表接口统一走校区过滤辅助函数，并加测试。
- 风险：口径不一致导致对不上账。对策：金额口径在本文档固定（第 8 节），接口与前端共用同一套定义。
