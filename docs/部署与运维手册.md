# 学校管理系统 — 部署与运维手册

更新日期：2026-09-14

## 1. 系统概览

自建教培机构管理系统，覆盖：组织与权限、课程、班级与分班、教室、排课、报读与课时、记上课与考勤、成绩、课堂点评、作业、订单与收款、退费、学员账户、报表中心。

技术栈：

| 层 | 技术 |
| --- | --- |
| 前端 | React 18 + TypeScript + Vite + ECharts |
| 后端 | Node.js 24 + TypeScript + Fastify |
| 数据库 | PostgreSQL 16+ |
| 部署 | Docker Compose（可选）+ Nginx |

## 2. 环境要求

- 操作系统：Windows 10/11 或 Linux（推荐 Ubuntu 22.04+）
- Node.js：22 以上（开发与构建用 24 验证通过）
- PostgreSQL：16 以上
- Docker + Docker Compose：仅容器化部署时需要
- 浏览器：Chrome / Edge / 360 极速（推荐最新版）

## 4. 本地开发

```powershell
# 1. 安装依赖（首次）
pnpm install

# 2. 准备数据库（已有则跳过）
#    默认连接串：postgres://school:school@localhost:5432/school
#    测试库：postgres://school:school@localhost:5432/school_test

# 3. 执行数据库迁移
pnpm --filter server run migrate

# 4. 启动后端（端口 3000）
pnpm --filter server run dev

# 5. 启动前端（端口 5173）
pnpm --filter web run dev
```

环境变量（在项目根目录 `.env` 或系统环境变量中设置）：

```env
DATABASE_URL=postgres://school:school@localhost:5432/school
JWT_SECRET=请替换为随机长字符串
PORT=3000
```

> 注意：本机若 `pnpm dev:web` 因沙箱权限报 esbuild 读目录错误，可改用生产构建 + 预览：
> `pnpm --filter web run build` 然后 `pnpm --filter web run preview`。

## 5. 生产部署（Docker，推荐）

1. 准备服务器（2 核 4G 起步）并安装 Docker。
2. 上传代码到服务器，进入项目目录。
3. 配置环境变量：

```bash
export POSTGRES_PASSWORD='强密码'
export JWT_SECRET='随机长字符串'
```

4. 构建并启动：

```bash
docker compose -f docker-compose.prod.yml up -d --build
```

5. 访问 `http://服务器IP`，`/api` 由 Nginx 自动代理到后端容器。

6. 配置 HTTPS（推荐）：在服务器上用 Certbot 或云厂商证书，把证书挂到 web 容器的 Nginx 上，并把 443 端口对外开放。

## 6. 生产部署（不使用 Docker）

```bash
# 后端（用 pm2 守护）
cd server
npm install -g pm2
PORT=3000 DATABASE_URL=... JWT_SECRET=... pm2 start "node src/server.ts" --name school-server

# 前端（构建静态文件）
cd ../web
pnpm install
pnpm run build     # 产物在 web/dist

# Nginx：把 web/dist 作为站点根目录，并把 /api 反向代理到 127.0.0.1:3000
```

## 7. 数据库备份与恢复

备份脚本：`scripts/backup.sh`

```bash
DATABASE_URL=postgres://school:密码@localhost:5432/school ./scripts/backup.sh
```

脚本会导出带时间戳的 `.sql.gz` 到 `backups/`，并自动删除 30 天前的备份。

定时备份：

- Linux：`crontab -e` 添加 `0 3 * * * cd /opt/school-system && DATABASE_URL=... ./scripts/backup.sh`
- Windows：用「任务计划程序」每天 03:00 运行同一条命令（或在 WSL/Git Bash 中执行）

恢复：

```bash
gunzip -c backups/school-YYYYMMDD-HHMMSS.sql.gz | psql "$DATABASE_URL"
```

建议每季度做一次「恢复演练」，确认备份可用。

## 8. 升级流程

```bash
git pull                     # 1. 拉取新代码
pnpm install                 # 2. 更新依赖（有变化时）
pnpm --filter server run migrate   # 3. 执行新增的数据库迁移
pnpm --filter web run build  # 4. 重新构建前端
# 5. 重启后端进程 / 重建容器
docker compose -f docker-compose.prod.yml up -d --build
```

- 迁移文件只增不改，按文件名顺序执行，已执行过的不会重复执行。
- 升级前建议先跑一次备份。
- 回滚：代码可以 `git checkout` 回上一版本，但数据库迁移不可逆，重要升级前务必留备份。

## 9. 账号与安全

- **务必修改** `JWT_SECRET` 与数据库密码，不要使用示例值。
- `.env` 已被 `.gitignore` 排除，不要把它提交到仓库。
- 管理员初始账号请首次登录后立即修改密码。
- 权限模型：角色 → 适用校区 → 模块权限；员工可拥有多个角色。
- 关键操作（排课、记上课、成绩修改、订单收款、退费、课时调整）都会写入 `audit_logs`，可用于追责与对账。
- 家长/学生只能看到自己绑定的学员数据；教师只能看到自己任教的班级。

## 10. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 后端起不来，提示端口被占用 | 3000 端口被占用，改 `PORT` 或结束占用进程 |
| 提示数据库连接失败 | 检查 PostgreSQL 是否启动、`DATABASE_URL` 是否正确、账号密码是否匹配 |
| 前端构建报 esbuild 目录权限错误 | 沙箱限制，改用 `vite build --configLoader runner`（项目脚本已内置） |
| 页面能打开但接口 401 | 登录过期，重新登录；或 `JWT_SECRET` 被修改导致旧 token 失效 |
| 报表加载慢 | 数据量大时先缩小时间范围；确认 `012_report_permissions.sql` 的索引已执行 |
| 课时与流水对不上 | 所有课时变动都在 `hour_transactions` 有记录，用它逐条核对；不要直接改余额 |

## 11. 测试与验收

```bash
# 后端自动化测试（需要 school_test 数据库）
cd server
node --test --test-concurrency=1 "test/*.test.ts"

# 类型检查
node_modules/.bin/tsc --noEmit          # server
cd ../web && node_modules/.bin/tsc --noEmit

# 前端构建
node_modules/.bin/vite build --configLoader runner
```

冒烟验收（每次部署后建议执行）：

1. 管理员登录，能看到全部菜单
2. 新建学员 → 报读课程 → 生成课时账户
3. 建班级 → 分班 → 排课（重复时段应被拦截）
4. 记上课点名 → 课时与金额同步扣减
5. 录成绩 → 家长端能看到
6. 点评与作业 → 家长端能看到并回写已读
7. 开订单收款 → 账户余额与流水正确
8. 报表中心各页签数据正常
